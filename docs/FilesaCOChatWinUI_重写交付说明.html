6 · 本次移植遇到的依赖 / 配置问题与解决

问题（用户截图所示）：启动 exe 时弹出「This application requires the Windows App Runtime Version 1.6 (MSIX package version >= 6000.373.1641.0)」，进程立即退出（退出码 22）。这不属于原缺陷清单，是 WinUI 3 移植引入的部署依赖问题。
环节核查事实处理
Windows SDK用户已补装，实测 C:\Program Files (x86)\Windows Kits\10\ 下 Include/Lib/bin/UnionMetadata/XamlCompiler 齐全，版本 10.0.28000.0。已满足无需额外处理；mt.exe 清单工具由 BuildTools NuGet 提供，Windows SDK 补齐后不再缺工具链
运行时版本WindowsAppSDK 1.6.250108002 包内 MicrosoftWindowsAppSDKFoundationAppXVersion.props 与 WindowsAppSDK-VersionInfo.json 硬绑定 6000.373.1641.0；本机装的是 Microsoft.WindowsAppRuntime.1.6 = 6000.519.329.0版本本身更高，但单纯比对版本不是根因
根因：DDLM 缺失系统只存在 4000.* 与 2.6.5.0 的 Microsoft.WinAppRuntime.DDLM.* 包，没有 1.6 配套的 DDLM 动态依赖包；自动注入的 MddBootstrapAutoInitializer.cs（WindowsPackageType=None 时由 SDK 自动启用）判定无兼容运行时并弹窗没有让用户去点「是」安装运行时——那会让「无需安装依赖」的原版行为退化
解决方案NuGet 包内自带 12 个 MSIX payload（x64/x86/arm64 各 4 个）设置 WindowsAppSDKSelfContained=true + WindowsAppSdkBootstrapInitialize=false：构建时把运行时 DLL 解包到输出目录，彻底移除机器级 Windows App Runtime / DDLM 前置条件，同时禁用弹窗用的自动引导初始化器
附带修正自包含模式下 mt.exe 对 app.manifest 中 2010 命名空间的 dpiAwareness 报 81010003 编写警告；RID 一度写死 x64删除冗余的旧 dpiAwareness 声明（Win10+ 只需 2016 PerMonitorV2）；RuntimeIdentifier 改为可被 -r win-x86 / -r win-arm64 覆盖的条件默认值
验证：输出目录 269 个文件 / 90 MB，含 Microsoft.WindowsAppRuntime.dll、Microsoft.ui.xaml.dll 等；重新启动 exe 进程存活至有界超时（124，此前为 22），枚举窗口标题得到 Filesa COChat 5.1 · WinUI 3、Responding=True，窗口列表中不再出现任何运行时缺失弹窗。

7 · 功能取舍与兼容性限制

7.1 有意的行为变更（安全整改，无法两全）

变更原行为现行为影响

7.3 平台与分发限制

  • 仅 Windows：原版是 Windows exe（Python/Tk 理论上可跨平台运行），重写后绑定 WinUI 3，最低 Windows 10 1809（10.0.17763.0）。默认 x64；x86 / ARM64 需显式 -r 指定，本次只实机构建并验证了 x64。
  • 不再是单文件：原版 PyInstaller 单文件 23 MB；自包含输出为 266 个文件 / 90 MB 的文件夹（换取「无需安装运行时」）。本次已实测尝试 PublishSingleFile + .NET self-contained：exe 成功生成（63 MB，压缩后更小），但启动即崩溃 COMException 0x80040111 ClassFactory 无法供应请求的类（Microsoft.UI.Xaml.Application.Start → WinRT 激活工厂）——WinUI 3 的 XAML/WinRT 组件必须从磁盘按原路径加载，单文件 bundle 的内存加载机制不适用；同时触发 NETSDK1244 旧版提取模式警告。本机 7-Zip 为 NanaZip 且无 SFX 自解压模块，自解压单 exe 路径也不可行。结论：WinUI 3 无法在不引入第三方打包器 / MSIX 的前提下交付单文件 exe；失败的产物保留在 dist/_experiments/ 作为证据，勿使用。
  • .NET 8 运行时：当前为框架依赖部署，目标机器需 .NET 8 Desktop Runtime（本机 8.0.34 已装）；也可用 --self-contained true 发布以彻底免安装。
  • 无 Authenticode 签名：与原版一致（原 exe 也无签名目录），SmartScreen 可能对未签名 exe 提示。
  • 更新链路：仍只提示、不自动下载，也未校验发布物签名/哈希（D8 只补了输入校验）。若将来做自动更新，需补齐签名验证。
  • UI 细节非 1:1 复刻：Tk PopupNotification 的淡入淡出 / 位移动画改为 Windows 系统通知（通知中心 toast）与 WinUI ContentDialog；主题图标与布局按 Fluent 风格重排。文案、流程、功能项保持一致。

10 · 局限与后续建议

  • 未做真实局域网多机实测 / 抓包：20 项网络用例在 loopback + 临时端口上跑真实 TCP/UDP socket，但未在多台物理主机、真实交换机广播域中验证 255.255.255.255 广播与 /24 扫描。建议上线前做一次 3 机联调。
  • 未做运行时抓包比对：原版 exe 全程未执行（静态逆向），因此「线格式逐字节一致」是与 protocol_reference.py 冻结常量及字节码常量比对的结果，不是与原版进程抓包比对。
  • 未做长时间压力 / 断线重连 / 弱网测试：迁移重试、文件传输中断、大文件（接近 2 GiB）边界只做了逻辑与单元覆盖。
