一句话结论：这是一个由 PyInstaller 打包的单文件 Python 3.13 桌面应用，整个业务逻辑压缩在唯一脚本 main.py 中；它是 MIT 开源项目 Filesa COChat 的 5.1 版，一个「无需专用服务器」的局域网聊天工具，使用 Tkinter 做界面、原生 socket 做明文 TCP/UDP 通信、Pillow 处理图标、requests 检查 GitHub 更新，并在 5.1 中新增了带 SHA-256 校验的文件传输与服务器自动迁移。

对开发者最重要的三个发现
  1. 高危 聊天协议中定义了 COMMAND:<目标用户>:<命令>，命中本机用户名的客户端会执行 subprocess.run(command, shell=True, timeout=5)。协议无认证、无加密，任何能连上 11451/TCP 的局域网主机都可伪造目标用户名触发执行。
  2. 功能缺陷 静态字节码中，receive_messages 收到普通聊天报文 user:msg 后只调用本地 add_message，没有转发给其他客户端；客户端又只与服务器保持一条 TCP 连接。据此推断：服务器发出的消息能广播到所有客户端，但客户端发出的消息只在服务器窗口显示，客户端之间互不可见（推断，建议运行时复核）。
  3. 工程问题 所有报文都是「冒号分隔的裸字符串 + 单次 recv(1024)」，没有长度帧、转义与消息边界，存在粘包/半包与协议注入；控制指令与聊天文本共用同一命名空间。

4.1 服务器迁移时序

服务器关闭 (WM_DELETE_WINDOW → on_closing → initiate_migration)
  ├─ select_new_server()  从 user_list 中随机挑一个 ≠ 自己的用户
  ├─ 向该用户的 socket 单发  PROMOTE:<self.host>
  │     └─ handle_promotion(): disconnect_all() → create_chatroom() → 成为新服务器
  ├─ 向其余所有 socket 广播 MIGRATE:<new_server_ip>
  │     └─ handle_migration(): migrating=True → disconnect_all()
  │            → join_chatroom(new_ip)；失败则 5s 后 reconnect_to_server()
  └─ time.sleep(1) 后释放旧连接（无确认握手、无版本号/任期）

推断 迁移依赖「先提升新服务器、再通知其余人」的时序与固定 1 秒延迟，缺少确认/重试仲裁，网络抖动下可能出现双服务器或无服务器；建议运行时压测验证。
